# 批次谱系召回库（batch genealogy recall library）

第四个、与 v1/v2/flash/handoff 完全独立的入口（`python -m cold_exposure.recall`，
仅用 Python 3.11+ 标准库与内置 `sqlite3`）。它回答的问题是：冷链批次经过拆批、
混批之后，若某些批次被召回，风险沿谱系波及哪些**整批**后代，以及这些受影响批次
的**剩余库存**各有多少、合计多少。它**只产出合成召回演练依据，不判定法律范围、
赔偿责任或处置决定**；既有全部入口的文件、CLI 与数值行为均保持不变。

## 输入

1. 批次 CSV（UTF-8，精确有序表头）：`lot_id,quantity_kg`
2. 流向 CSV（UTF-8，精确有序表头）：`source_lot,target_lot,quantity_kg`

两份输入都按字节各读取一次，同一批字节同时用于 SHA-256 哈希、解析和入库归档；
原文件之后被移动或删除，数据库内仍保留原文与来源位置，召回查询与复核都不再需要
原文件。

### 数量契约（不经 float）

- `quantity_kg` 为**正的有限十进制**：1–12 位整数位，可带 1–6 位小数，正则
  `^[0-9]{1,12}(\.[0-9]{1,6})?$`。不接受符号、指数记法、千分位、首尾空白或
  裸小数点；`0` 与负数拒绝。前导零（如 `007.5`）合法，输出一律规范化为恰六位
  小数（`7.500000`）。
- 解析不经过 `float`：字面量经严格正则匹配后直接换算为**整数微公斤**
  （1 kg = 1,000,000 微公斤），全部求和、比较、剩余量计算都是整数运算，不涉及
  任何舍入上下文。12 位整数位上限保证每批各项微公斤总量恒在 SQLite 64 位整数
  范围内（单批上限约 10^12 kg，远超冷链实际）。

### 结构契约（任何拒绝都带文件名与物理行号，表头为第 1 行）

按以下顺序校验，首个违规即拒绝：

1. `lot_id` 全局唯一，非空、无首尾空白、不含换行；边以 `(source_lot, target_lot)`
   唯一，同一对批次的合并流量必须写成一行。
2. 每条边的两端都必须已在批次文件中声明；**自环拒绝**。
3. 谱系必须无环（先查结构，再查流量平衡）。边行可以任意乱序（子批可先于其父批
   出现）；拓扑序用确定性算法计算（每步在可入队批次中取 `lot_id` 最小者），与
   输入行序无关。环报错列出所有处于环上或环下游而无法拓扑排序的批次。
4. **无入边者为原料**。其余批次的入量合计必须**恰好等于**其声明量；原料声明量
   不受入量约束。
5. 每批出量合计**不得超过**其声明量，因此剩余库存 `声明量 − 出量` 永不为负。

仅含表头的流向文件合法（全部批次为原料）；批次文件至少需要一个批次。

## 召回语义

- 召回查询接受一个或多个批次 ID；**未知 ID 拒绝**（列出全部未知 ID，退出码 2），
  重复给出的起点去重。
- 风险沿边传播到**整批**后代（传递闭包）：只要某批被任一召回起点直接或间接到
  达，该批即整体受影响。**流量公斤数从不被当作污染质量**——1 kg 的边与 1000 kg
  的边传播效果相同。
- 输出每个受影响批次的 `声明量 / 出量 / 剩余量`（剩余 = 声明 − 出量）及合计剩余
  库存。**汇合（菱形）与多起点重叠不得重复计量**：每个受影响批次无论被多少条
  路径、多少个起点到达，只计量一次。
- 证据追到输入行：每个批次给出其在 `lots.csv` 的物理行号，每条传播边给出其在
  `flows.csv` 的物理行号（`affected_edges` 为两端均受影响的全部边，按输入行序）。
- 输出按规范拓扑序排列，JSON 键排序，数量为规范六位小数字符串；相同数据库与
  相同起点必得字节一致的结果。

## SQLite 结构（schema_version = 1）

| 表/视图 | 作用 |
| --- | --- |
| `ingestion_run` | 单行：schema 版本、批次/边/原料计数、声明总量/流量总量/剩余总量（规范文本）与政策说明；复核时全部由明细行重算比对 |
| `source_document` | 两份原文（`lots_csv`、`flows_csv`）、SHA-256、字节数与全文 |
| `source_location` | 每份原文的调用时来源路径（按传入原样记录）与记录位置：表头行号、首数据行号、数据行数 |
| `lot` | 批次：规范拓扑序 `ordinal`、声明/入量/出量/剩余量（**规范文本 + 整数微公斤双表示**，互核）、原料标志、`lots.csv` 行号 |
| `flow` | 边：`edge_id` 按输入行序从 0 密集编号、两端外键、流量双表示、`flows.csv` 行号；`(source,target)` 唯一、禁自环由 `UNIQUE`/`CHECK` 强制 |
| `v_lot` / `v_flow` | 稳定排序的只读查询视图 |

外键在每个连接开启（`PRAGMA foreign_keys = ON`），建库后运行
`PRAGMA foreign_key_check`。数量双表示仿照交接集市的双时间列：文本用于报告，
整数微公斤用于 SQL 端**精确**求和（SQLite 整数为 64 位精确运算），复核时两者
互核。

## 确定性、原子发布与失败恢复

- 无时钟读取、无机器绝对路径、无随机量；相同输入字节重建得到逻辑一致、SQL 转储
  相同的数据库（测试用 `iterdump()` 比较两个独立库）。
- `build` 先在目标同目录写隐藏临时文件，完整建表、装载并通过全部库内复核后，才
  用一次 `os.replace` 替换目标；任何读、解析、计算、写入或复核失败都删除临时
  文件，**旧库保持字节不变**，可修正后直接重跑。目标为符号链接时拒绝。
- `verify` 以只读 URI（`mode=ro`）打开既有库，执行：外键检查；文本与微公斤互核；
  由边表精确重算每批入量/出量并与存储值比对；剩余量=声明−出量、出量≤声明、
  原料标志⟺入量为零、非原料入量=声明逐批复核；运行摘要重算；边 ID 密集且行号
  严格递增；存储边仍构成 DAG 且拓扑序为规范序；源文档哈希与归档字节一致；以及
  **用归档原文重建整个模型并与已存批次/边逐行比对**。因此移走输入文件后仍可
  完整复核。
- `recall` 同样以只读 URI 打开数据库，只读库不读源文件；查询本身不修改数据库
  （测试断言查询前后数据库字节哈希不变）。

## 命令与 Python API

```sh
# 建库（临时构建 + 原子替换）
python -m cold_exposure.recall build \
    --lots examples/recall/lots.csv \
    --flows examples/recall/flows.csv \
    --output run/recall/genealogy.db

# 只读召回（可多个起点；未知 ID 拒绝）
python -m cold_exposure.recall recall \
    --database run/recall/genealogy.db --lot RAW-MILK --lot RAW-SUGAR

# 只读复核
python -m cold_exposure.recall verify --database run/recall/genealogy.db
```

Python 调用：

- `cold_exposure.recall.build_database(lots_csv, flows_csv, output_db)` → 内存模型
- `cold_exposure.recall.recall_from_database(db_path, lot_ids)` → 召回结果字典
- `cold_exposure.recall.verify_database(db_path)` → 复核摘要
- 分步 API：`build_model(lots_bytes, flows_bytes)`、`compute_recall(lots, edges, ids)`

失败一律以退出码 2 结束并在标准错误给出带文件与行号的原因。

## 合成示例与手算核对

`examples/recall/` 为原创合成数据（虚构乳品/燕麦谱系，不代表任何真实企业、批次
或监管判定）。批次与边行均故意乱序。要点：

- 原料 `RAW-MILK`（2000）经 `BASE-A`/`BASE-B` 两条路径汇入 `BLEND-C`（菱形汇合），
  再拆为 `PACK-C1`/`PACK-C2`；`BASE-B` 另与 `RAW-VANILLA` 混成 `FLAVORED-D`；
  `RAW-OATS → PACK-OATS` 为无关支链。`BLEND-C` 出量 1000.5 < 声明 1200，剩余
  199.5，是**混批部分消耗**。
- 召回 `RAW-MILK`：受影响 7 批（MILK、BASE-A、BASE-B、BLEND-C、PACK-C1、
  PACK-C2、FLAVORED-D），剩余合计 `600+200+0+199.5+600+400.5+250.25 =
  2250.25` kg；BLEND-C 经两条路径到达只计一次。
- 召回 `BASE-B` 与 `BLEND-C`（多起点重叠）：受影响 5 批，合计
  `0+199.5+600+400.5+250.25 = 1450.25` kg。
- 召回 `PACK-OATS`：仅自身 300 kg，与乳品支链互不波及。
- 召回 `RAW-MILK` 与 `RAW-SUGAR`：并集 8 批，合计 `2250.25+200 = 2450.25` kg。

测试另覆盖：循环（含自环、多节点环、环带下游）拒绝、超耗拒绝、入量不等拒绝、
未知引用、重复批次/边、数量词法（六位小数上限、指数/负号/空白拒绝、微公斤精度
求和）、乱序边接受、行号证据、写入失败保旧、重跑确定性与篡改复核失败。

## 当前约束

单进程全量计算；谱系规模以内存与单库文件为限。剩余库存只按声明量与记录出量
推算，不表示实物盘点；本工具不做运输温度分析（由 v1/v2 入口负责），不判定批次
质量，只按给定谱系做确定性的图传播与库存汇总。
